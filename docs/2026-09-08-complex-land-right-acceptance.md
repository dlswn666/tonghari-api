# 다동 단지 대지권 조회·개발 입력 완료 기준

## 요구사항과 정본

사용자 확정: 개발 상계주공10단지(재건축/신탁 시행/정비계획 입안)의 소유주 없는 물건지에 실제 API가 제공하는 대지권 값만 입력한다. 별도 값·목록 승인은 요구하지 않으며 무자료·NULL은 그대로 둔다. 2026-09-08 사용자가 공용 API의 단지형 조회·동호 매칭 수정과 배포, 개발 검증 및 실제 입력까지 요청했다.

맥락: Obsidian `Projects/통하리-명부-GIS-에이전트-직접입력-스킬-설계.md`의 J4/J10/J13/J14/J18은 대상 동호 기준 식별, 명시적 정규화, 중복 방지, 호실별 부분 적용, 쓰기 전 상태 재검증을 요구한다. 오래된 단일 표제부 제한은 이번 명시 요청에 따라 다동 단지를 지원하도록 확장한다. 사업 유형·소유자·법정 구역 여부를 필지로 자동 추론하지 않는다.

## 역할과 실행 순서

1. 기획/분석: 현재 API·Web·스킬 계약 및 실제 공개 원문 형태를 대조한다.
2. 구현: API의 정확한 대상 동 선택·완전한 DB 목록 조회, 스킬의 숫자 동호 표기 정규화를 분리한다.
3. 리뷰: 독립 리뷰로 다동·중복·범위 누락·다른 조합·기존 값 보호를 확인한다.
4. 검증: 자동 테스트/빌드 → 배포 이미지·개발 실조회 → 원문 검토·보호 SQL 적용 → DB 전수 대조 순서로 진행한다.

## 수용 체크리스트

- [x] 한 PNU에 여러 표제부가 있어도 정확히 일치하는 대상 동/건물 근거가 하나일 때만 그 동의 범위를 검토한다. 전체 응답을 성공으로 가장하거나 임의의 첫 동을 고르지 않는다.
- [x] 대상 미일치, 정규화 후 중복, 부속지번/원천 페이지 누락, 변경된 DB 상태는 적용 후보로 만들지 않는다.
- [x] 2,654건 이상의 물건지 목록을 모두 읽고 정렬·중복·페이지 완결을 검증한다.
- [x] 숫자 동/호의 접미사와 선행 0만 같은 식별자로 대조한다. 원문/DB 표시값은 바꾸지 않고 문자형·지하·복합 호수는 추정하지 않는다.
- [x] API가 제공하지 않은 대지권을 필지 전체면적·다른 호실 값·0으로 대신하지 않는다. 반복된 동일 분자를 중복 합산하지 않는다.
- [x] 원래의 인증·개발/운영 DB 분리·외부 API 제한·출처·낙관적 잠금 및 NULL-only 입력 조건을 유지한다.
- [x] 기존 보호 Web envelope와 검토 helper의 호환성을 검증한다. 계약 변경이 필요하면 Web dev 배포·검증 게이트를 별도로 수행한다.
- [x] API 전체 테스트·빌드, 스킬 forward test/validator, 독립 리뷰를 통과한다.
- [x] 현재 API 배포 경로에서 개발/운영 영향 및 보호 환경 게이트를 확인한다. 배포와 운영 DB 적용은 별개이며 운영 DB는 쓰지 않는다.
- [ ] 개발 DB에 실제 적용 후 입력 수·미입력 사유·값/출처·소유주 0을 재검증한다. 준비된 목록이나 SQL만으로 완료라고 하지 않는다.

기존 상가 포함 범위, 건물 윤곽, 소유주 생성, 운영 DB 입력은 이번 변경에 포함하지 않는다.

## 구현과 자동 검증

- 기존 canonical 자동동기화 분류기·writer는 변경하지 않았다. transient 공식자료 조회에서만 exact 집합/아파트 표제부와 대상 숫자 동을 확인한다.
- `scopeResolution.buildingRootCount: 1`은 조회 대상에서 유일하게 선택한 동의 root 수다. PNU의 전체 건물 수를 1개로 축약했다는 뜻이 아니다. 전체 표제부·부속지번·외필지 근거는 검증과 digest에 남는다(`scope-evidence@2`).
- 같은 단지 부속지번을 여러 관리번호가 공유하는 경우 기존 base/attached 중복 제거와 별개로 관리번호별 전체 원문·개수를 재검증한다. 다른 동 범위가 상이하거나 실제 개수가 어긋나면 HOLD다.
- DB 목록은 안정된 ID 순서와 exact count로 최대 50,000행을 전수 조회한다. count 변동·중복·역순·중간 빈 페이지·조회 오류는 부분 결과를 반환하지 않는다.
- 관련 회귀 44/44, 전체 1,626건 중 1,622 통과/실패 0/기존 skip 4, TypeScript 빌드 및 property-building writer guard 통과. 첫 sandbox 실행은 localhost `EPERM`으로 실패했고 포트 허용 실행에서 다시 통과했다.
- 전역 대지권 검토 스킬 forward suite·AST DTO 대조·quick validator를 구현자와 독립 리뷰어가 각각 통과했다. 별도 값·manifest 승인은 요구하지 않는다.
- 실DB 전량 입력 전에는 보호된 원문 파일 캡처, 전량 accounting/분할 처리량, 기존에 확인한 대상 층 불일치의 보류를 별도로 검증해야 한다. 이 문서의 자동 검증 통과는 DB 입력 완료를 뜻하지 않는다.
