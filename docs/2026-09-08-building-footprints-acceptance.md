# 동별 윤곽 조회·상계10 개발 적재

## 요구사항과 정본

- 사용자: 동별 윤곽 수집·저장을 먼저 진행. 기존 상계주공10단지 재건축 개발 구역의 실제 API 값만 사용하며 없는 값은 추정하지 않는다.
- Obsidian `Projects/통하리-비즈니스로직/05-GIS-토지-동의.md:148-152`: 필지 경계를 유지하고 특정 동을 선택해 층·호로 탐색한다.
- Obsidian `Projects/통하리-재건축-갭-감사.md:146`: P3 건물 공간정보 실측 선행. 과거 DONG_NM 매칭률 90.1%는 실측 근거로 사용하지 않는다.
- 이번 범위는 원천 조회 및 동별 geometry 저장까지다. 지도 렌더·클릭, 소유주·동의·대지권 면적 변경은 제외한다.

## 역할 및 실행 순서

1. 기획/분석: 정본, 공식 API 속성, 기존 MCP 계약 및 개발 DB 구조 대조.
2. 구현: 최신 main에서 별도 작업 브랜치. 읽기 전용 `lookup_building_footprints_v1` 추가. 기존 14종 전체 조회는 그대로 유지.
3. 리뷰: 별도 에이전트가 입력/출력 검증, 실패·페이징 처리, 자격증명 보호, 저장 대상 범위 독립 검토.
4. 검증: 합성 회귀/전체 테스트/빌드 → 동일 코드 배포 → 실제 상계10 응답 → 27개 주거동 대조 → 개발 DB 적재 후 재조회.

## 수집 계약

- 공식 후보: VWorld `https://api.vworld.kr/req/data`, 레이어 `LT_C_BLDGINFO`.
- 공식 문서: `https://www.vworld.kr/dev/v4dv_2ddataguide2_s002.do?svcIde=bldginfo`.
- EPSG:4326 GeoJSON Polygon/MultiPolygon과 `dong_nm`, `bld_nm`, 층수 등 허용 속성을 보존한다.
- 레이어에 PNU/건축물대장 PK가 있다고 가정하지 않는다. 호출은 크기가 제한된 BBOX 및 페이지 단위이며 임의 URL/레이어/필터 입력을 받지 않는다.
- 기존 인증, gis:read, 요청 deadline, 출력 예산, 비밀정보/소유자 정보 차단을 유지한다.
- 원본 도형을 단지 전체 필지로 대체하거나 임의 단순화·생성하지 않는다. 잘못된 도형과 불완전 응답을 NO_DATA/완전 성공으로 숨기지 않는다.
- provider/source/asOf/attribution, 원천 feature ID 및 페이지 완결성 보존. asOf는 조회 시각이며 원천 갱신일을 뜻하지 않는다.
- 자료별 실제 이용허락을 확인한다. 전체 GIS 결과에 대한 일괄 저장 금지 또는 일괄 허용 규칙을 새로 만들지 않는다.

## 개발 DB 저장 계약

- 개발 프로젝트 `yxypndgipnxrdfyctmvh`, union `dc93c777-58ce-40d7-9c79-8c4753fa1103`, slug `sanggye10`의 실존·관계 재확인.
- 기존 주거동 목록과 원천의 정확한 동명, 공간 위치 및 층수 등 독립 속성을 대조. 응답 순서/최근접 추측으로 연결 금지.
- `buildings.boundary`는 기존 MULTIPOLYGON/SRID 4326 형식 사용. 스키마 변경 없이 가능한지 우선 검증한다.
- 기존 non-NULL 값, 삭제된 행, 다른 조합과 공유된 대상을 보호한다. 출처는 기존 참조 메타데이터 안의 별도 footprint 근거로 명확히 구분한다.
- 짧은 트랜잭션에서 대상 잠금, 사전 상태 및 기대 건수 검사. 실패 시 전체 롤백. 외부 조회는 트랜잭션 밖에서 수행한다.
- 적재 후 유효성/좌표계/동별 1:1 연결/원문 도형 일치 및 비대상 불변 재검증.
